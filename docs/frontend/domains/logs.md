## 页面与交互

实时轮询、历史读取、清空/清理命令的所有者与协议均未改变；页面视图状态由工作区和受控面板持有；工具栏暂停入口与清空、历史、重试、Activity 协作的策略见下文。

### 1. 定位与边界

| 内容 | 唯一归属 | 说明 |
| --- | --- | --- |
| 页面壳 | `pages/logs/LogViewer.tsx` | 只渲染 `app-page`/`app-stack-section`、页头、状态指示与工作区 |
| 跨面板视图状态 | `features/logs/components/LogsWorkspace.tsx` | 内容模式、级别、搜索、折叠、自动滚动、通知与确认动作；组合 `useLogsSession` |

| 工具栏 | `features/logs/components/LogsToolbar.tsx` | 自动滚动/折叠开关、级别、搜索、暂停、清空与导出入口 |

| 解析/过滤/折叠视图 | `model/logModel.ts` 的 `buildLogView` | 纯函数；工作区只做一次派生，列表与导出共享结果 |
| 导出文本与文件名 | `model/logExport.ts` | 纯格式规则；Blob/objectURL/anchor 下载仍由工作区执行 |

维护约束：

- 不改变 `/agent/logs/*` 端点、`lines` 参数、1250ms 轮询、快照替换语义、历史请求序号与 AbortSignal 裁决。
- 不改变列表行结构、折叠规则、摘要识别、搜索匹配范围与导出格式（仍导出过滤后的折叠前行）。
- 不新增 Query、业务存储、cursor/offset 或跨标签页共享。
- 工具栏提供暂停/继续入口与对应空态；视觉约束见 §6。

### 2. 组合与状态边界

```
LogViewer（页面壳：PageHeader + FloatingStatusIndicator）
└─ LogsWorkspace（useLogsSession + 共享视图状态 + 导出动作）
   ├─ LogNotice（命令结果）
   ├─ LogContentModeTabs（摘要/原始）
   ├─ LogsToolbar（开关/级别/搜索/暂停/清空/导出）
   ├─ LogConsole（列表 + 自滚动容器）
   ├─ HistoryLogPicker（文件列表/选择/清理）
   └─ ConfirmDialog（清空/清理确认）
```

| 状态 | 所有者 | 进入历史 | 返回实时 | Activity 隐藏/恢复 | 真正卸载/刷新 |
| --- | --- | --- | --- | --- | --- |
| 实时缓冲、轮询计时器、错误、手动暂停 | `RealtimeLogStream`（页面实例） | `stop()` + `clear()`，暂停标记保留 | 恢复手动暂停后由 `enabled` 立即重读 | 计时器停止/重建；暂停标记保留 | 新实例，缓冲与暂停重置 |
| 历史文件列表、选择、读取相位与错误 | `HistoryLogSession` | 选中并读取 | 取消读取、清空选择 | 取消列表/读取，恢复重读列表并重试被取消的当前文件 | 全部重置 |
| 内容模式、级别、搜索、折叠 | `LogsWorkspace` 本地状态 | 保留 | 保留 | 保留 | 重置 |
| 自动滚动开关 | `LogsWorkspace` 本地状态 | 关闭并禁用 | 打开 | 保留 | 重置 |
| `scrollTop` Effect | `LogConsole` | 不执行 | 恢复执行 | Effect 清理/重建 | 随组件销毁 |
| 命令在途槽位 | `useLogsSession` | 清理入口禁用 | 保留 | 卸载取消本地等待 | 重置 |
| 通知与确认动作 | `LogsWorkspace` | 保留 | 保留 | 保留 | 重置 |
| 导出文本/文件名 | `model/logExport.ts` 纯函数 | — | — | — | — |

- **页面无会话与请求。** `LogViewer` 不调用日志 hooks/API，只组合工作区。
- **面板全部受控。** 工具栏、列表、历史选择器不订阅 `RealtimeLogStream`/`HistoryLogSession`，也不持有选择；所有回调与数据来自工作区。内容模式分段的测量、`ResizeObserver` 与键盘处理留在分段组件内。
- **自滚动靠近滚动容器。** 开关状态需要被工具栏与“进入/返回历史”共享，因此归工作区；`scrollTop` Effect 与 `ref` 归 `LogConsole`，只在实时模式且开关打开时滚到底部。
- **模式/过滤只派生一次。** 工作区的 `useMemo` 调用 `buildLogView`；列表使用 `visible`，导出使用 `filtered`，两者都来自同一快照，避免切换面板时重复摘要或折叠。

### 3. 暂停、清空与重试

工具栏暂停按钮只在实时模式渲染，点击调用 `RealtimeLogStream.pause()`/`resume()`；历史模式隐藏该按钮（历史读取不受暂停影响）。按钮可见文本在“暂停/继续”之间切换，可访问名称同步为“暂停实时日志/继续实时日志”，不使用与动作冲突的 `aria-pressed`。

| 交互 | 策略 | 依据 |
| --- | --- | --- |
| 手动暂停 | 取消在途读取，之后计时器 tick 跳过；Activity 与 `document` 可见性变化都不清除暂停 | `realtimeLogStream.ts` 既有语义 |
| 暂停后点“重新加载” | 先 `resume()` 再立即重读，不在暂停守卫上静默空转 | `LogsWorkspace.retryActiveLogs` |
| 暂停后清空 | 命令记录开始前的 `paused`；成功清空缓冲后仅当此前未暂停时 `resume()`，手动暂停保持 | `clearRealtimeLogsCommand` 的 `RealtimeLogCommandPort.paused` |
| 暂停 → 进入历史 → 返回实时 | `backToRealtime()` 先恢复暂停再退出历史；进入历史已清空缓冲，避免回到“已暂停且空缓冲” | `useLogsSession.backToRealtime` |
| 暂停且无日志 | 空态显示“实时日志已暂停，继续后重新读取” | `LogConsole` |
| 历史模式清理 | 保持禁用；清理成功后的 `reconcileSelection` 不会绕过页面的自动滚动恢复 | `HistoryLogPicker.cleanupDisabled` |

清空/清理失败、取消与卸载等待的裁决不变：失败保留缓冲/列表，确认弹层保持打开；页面卸载只取消本地等待，服务端已收到的动作不回滚。

### 4. 过滤、导出与自滚动

- 摘要/原始、级别、搜索与折叠仍由 `buildLogView` 依次应用；搜索不区分大小写，匹配时间、级别与消息。切换实时/历史、读取失败与重试不清空这些条件。
- 导出使用 `logView.filtered`（级别/搜索之后、折叠之前），每行 `[时间] [级别] 消息`；文件名 `maa-log-<UTC 日期>.txt` 与迁移前一致。格式与日期由 `model/logExport.ts` 固定，Blob/objectURL/anchor 的创建与撤销留在工作区；过滤结果为空时导出按钮禁用。
- 自动滚动默认开启；进入历史时关闭并禁用开关，返回实时时重新打开。开关重新打开会立即滚到底部；关闭后新日志追加不改变当前滚动位置。

### 5. Activity 与卸载

- Activity 隐藏/页面卸载：实时流 `stop()` 取消在途读取；历史会话取消列表与读取，进行中的读取转为 `cancelled`。工作区状态（模式、过滤、搜索、折叠、自动滚动、通知、确认动作）保留。
- Activity 显示：实时流按 `enabled` 与暂停标记决定是否立即重读；历史会话重读列表并重试被取消的当前文件。历史模式恢复不启动实时轮询。
- 浏览器刷新/真正重挂载：两个会话实例新建，缓冲、历史选择、过滤与滚动位置全部重置，与迁移前一致。

### 6. 兼容与视觉约束

- 端点、响应形状、轮询频率、请求取消、历史选择裁决、清空/清理命令端点与 `maxSizeMB:10` 均未变。
- 暂停策略的明确兼容差异：手动暂停时清空不再静默恢复轮询；从历史返回实时会恢复手动暂停。两者都有命令/页面级回归。
- 工具栏暂停按钮与暂停空态文案属于当前 DOM；默认态视觉由 `logs` 的主题/视口截图覆盖，更新基线应遵循[开发指南](../../development/README.md)的视觉回归流程。

## 实时流生命周期

### 1. 归属与边界

| 内容 | 唯一归属 | 说明 |
| --- | --- | --- |
| 实时缓冲、轮询计时器、请求取消与暂停状态 | `client/src/features/logs/model/realtimeLogStream.ts` 的 `RealtimeLogStream` | 会话数据，不进入 Query；同一时刻最多一个在途读取 |
| 页面生命周期接线 | `client/src/features/logs/hooks/useRealtimeLogs.ts` | 实例寿命、`useSyncExternalStore` 订阅、Activity 启停与 `document` 可见性转发 |
| 解析、级别归一、摘要、过滤与重复折叠 | `client/src/features/logs/model/logModel.ts` | 纯函数，不依赖 React、网络或 DOM |
| 工具栏、模式切换、自滚动与历史浏览 | `components/LogsWorkspace.tsx` 与工具栏/列表/历史选择器面板 | 视图状态；历史列表、选择与读取由[历史日志与清理协调](#历史会话与清理)的会话持有，组合边界见[日志领域面板](#页面与交互) |

实时流实例随日志页真正挂载创建。React Activity 隐藏会清理 Effects 但保留组件状态与实例，因此恢复后缓冲、过滤和选择仍在；浏览器刷新或真正重挂载会创建新实例，缓冲从头开始。实时日志没有持久化，也没有跨标签页共享。

### 2. 读取协议与快照语义

| 项目 | 当前值 | 依据 |
| --- | --- | --- |
| 端点 | `GET /api/agent/logs/recent?lines=200` | `features/logs/api` 的 `getRealtimeLogs` |
| 行数 | 客户端固定读取最近 200 行；服务端把 `lines` 限制在 1–500 | `REALTIME_LOG_LINES`、`server/routes/agentLogRoutes.js` |
| 轮询间隔 | 1250ms | `REALTIME_LOG_INTERVAL_MS`，与迁移前页面计时器一致 |
| 响应形状 | `LogEntry` 数组，每项含 `time`、`level`、`message` | 服务端 `getRealtimeLogs` 返回内存缓冲切片 |
| 缓冲方式 | 每次响应整体替换当前 200 行快照，不追加 | 服务端只返回最近行，没有增量标识 |

协议没有 `cursor`、`since`、`offset` 或递增序号，因此**增量游标不适用**。清空实时日志后，服务端内存缓冲归零，客户端在恢复轮询时重新读取空快照。

慢请求不会造成请求重叠：若一次读取超过 1250ms，到点的轮询被跳过；响应落定后，下一个到点轮询继续。这样在慢网络下实际刷新频率由响应时间决定，而不是叠加请求。

### 3. 请求控制与旧响应裁决

- 每次读取创建独立 `AbortController`，`signal` 一直传到 `fetch`。
- 同一时刻只保留一个在途请求；`start()`、`refresh()`、文档可见与手动恢复都经过同一守卫。
- 只有仍是当前请求且 signal 未中止的响应可以写入缓冲。页面隐藏、文档隐藏、手动暂停、清空前暂停、历史模式切换或新请求取代旧请求后，迟到响应一律丢弃。
- 请求失败保留上一份缓冲，只更新错误提示；用户点击“重新加载”调用 `refresh()`，已有在途请求时仍保持单在途语义。
- `AbortError` 不记为失败；取消不会清空缓冲，也不显示错误。

### 4. 生命周期与恢复

| 事件 | 实时流行为 | 页面结果 |
| --- | --- | --- |
| Activity 隐藏或页面真正卸载 | `stop()`：清计时器、取消在途读取，保留缓冲 | Effects 清理；历史会话同时取消列表与文件读取，进行中的读取转为 `cancelled`，不会留下 loading（见[历史日志与清理协调](#历史会话与清理)） |
| Activity 显示 | 先同步 `document` 可见性，再 `start()`：立即重读并重建 1250ms 计时器 | 缓冲、模式、过滤、搜索与折叠开关保留；历史会话重读文件列表并重试被取消的当前文件 |
| `document` 隐藏 | `setDocumentVisible(false)`：取消在途读取；计时器保留但守卫跳过发送 | 已有行继续显示 |
| `document` 可见 | `setDocumentVisible(true)`：立即重读，之后按间隔轮询 | 不等待下一个 1250ms tick |
| 手动暂停 | `pause()`：取消在途读取，之后计时器 tick 全部跳过；暂停状态不被 Activity 或文档可见性变化清除 | 已有行继续显示 |
| 手动恢复 | `resume()`：立即重读一次，之后继续按间隔轮询 | 用最新快照替换暂停期间的旧快照 |
| 历史模式 | 页面停止实时流并清空实时缓冲；`enabled=false` 保证 Activity 恢复不会重新启动轮询 | 返回实时时工作区先恢复手动暂停，再由 `enabled=true` 立即重读 |
| 清空实时日志 | `pause()` → `POST /logs/recent/clear` → 成功后 `clear()` 本地缓冲 → 此前未手动暂停时 `resume()` | 由 `logCommands.ts` 协调；清空期间不发轮询；此前未暂停时成功后立即重读服务端空快照，手动暂停时保持暂停；页面卸载只取消本地等待 |
| 手动暂停后的错误重试 | 先 `resume()` 再立即重读 | 工具栏“重新加载”不会在暂停守卫上静默空转 |
| 真正重挂载 / 浏览器刷新 | 新实例从空缓冲开始 | 过滤、搜索、折叠、历史选择与滚动状态全部重置 |

工具栏已有暂停/继续按钮，按实时模式显示；历史模式隐藏，暂停不影响历史读取。暂停状态由流持有，Activity 与文档可见性变化都不清除它。暂停、清空、历史返回与重试的组合策略见[日志领域面板](#3-暂停清空与重试)。

`enabled` 是页面级启用开关：历史浏览时为 `false`，Activity 恢复也不会启动轮询；重新为 `true` 时立即重读。它与手动暂停相互独立——在 hook 层关闭再开启页面级轮询后暂停仍然有效；日志页的“返回实时”入口会在重新启用前显式恢复手动暂停，因为进入历史已清空实时缓冲。

### 5. 解析与显示模型

`logModel.ts` 保留迁移前的解析规则：

- 实时项优先解析 `message` 内的 MAA 历史行格式 `[日期 时间][级别][可选线程] 内容`；没有内嵌时间戳时使用信封的 `time`，无法解析的时间显示为空。
- 历史文件按非空行拆分；支持带毫秒、级别别名（`ERR`、`WRN`、`WARNING`、`TRC` 等）和旧格式 `[日期 时间 级别] 内容`。
- 无法识别的级别归为 `INFO`；缺少时间的行在摘要模式下丢弃，但在原始模式下保留。
- 摘要模式识别任务回调（开始/完成/失败、设备连接、分辨率、截图方式、仓库识别）、任务状态更新、MAA 命令开始/结束、stdout/stderr 与常见噪声行；`DEBUG`、JSON 行和无时间行不进入摘要。
- 级别过滤与搜索在摘要（或原始）结果之后应用；搜索不区分大小写，匹配时间、级别与消息。导出使用过滤后的行，不使用折叠后的行。
- 折叠只合并**连续**且级别与消息都相同的行，显示次数并使用最近一个非空时间；关闭折叠时每行次数为 1。
- 自动滚动是页面视图状态：`LogsWorkspace` 持有开关，`LogConsole` 的 Effect 仅在实时模式且开关打开时把容器滚到底部；历史模式强制关闭自动滚动。

### 6. 错误与兼容

- 信封失败优先使用 `message`/`errorInfo.message`/`error`，缺省为“实时日志请求失败”；抛出的异常使用其 `message`，缺省为“暂时无法获取实时日志”。
- 失败不改变实时 API 的函数签名、端点或响应形状；`getRealtimeLogs(lines?, signal?)` 继续由域 API 提供并传递 signal。暂停期间的“重新加载”会先恢复流再读取，与未暂停时一样用最新快照替换错误。
- 实时流没有进入 TanStack Query，不改变 Query 的默认重取、Activity 或窗口焦点策略；清空、历史读取与清理命令也不进入 Query（见[历史日志与清理协调](#历史会话与清理)）。
- 工具栏暂停/继续入口与暂停空态文案属于当前交互；列表结构、CSS 与主题遵循既有视觉约束，见[日志领域面板](#页面与交互)。
- 轮询计时器、取消和旧响应守卫集中在 `RealtimeLogStream`；页面只负责生命周期与视图接线。

## 历史会话与清理

实时轮询与解析模型仍见[实时日志流生命周期](#实时流生命周期)。

### 1. 归属与边界

| 内容 | 唯一归属 | 说明 |
| --- | --- | --- |
| 实时缓冲、轮询计时器、在途读取与手动暂停 | `client/src/features/logs/model/realtimeLogStream.ts` | 已实现；历史读取不写入该缓冲 |
| 历史文件列表、当前选择、读取内容与读取/列表相位 | `client/src/features/logs/model/historyLogSession.ts` 的 `HistoryLogSession` | 会话数据，不进入 Query；同一时刻最多一个在途列表请求与一个在途文件读取 |
| 实时/历史模式、进入与返回、清空/清理命令的共用槽位 | `client/src/features/logs/hooks/useLogsSession.ts` | 组合两个会话；页面只消费该协议 |
| 清空实时与清理历史的请求协调 | `client/src/features/logs/model/logCommands.ts` | 纯命令函数，端口注入实时流/历史会话动作，便于直接测试 |
| 摘要/原始、级别、搜索、折叠、自动滚动、确认弹层与通知 | `client/src/features/logs/components/LogsWorkspace.tsx` 与工具栏/列表/历史选择器面板 | 最近的日志面板；不属于会话缓冲，组合边界见[日志领域面板](#页面与交互) |

历史文件列表与文件读取是页面会话数据，不是可缓存的普通资源：列表在每次页面显示时重读，读取没有分页缓存；两者都不进入 TanStack Query。

### 2. 实时与历史切换协议

| 动作 | 实时流 | 历史会话 | 页面 |
| --- | --- | --- | --- |
| 选择历史文件 | `stop()` 清计时器并取消在途读取；`clear()` 清空缓冲与错误 | 若在历史中先取消旧读取；设置当前选择并开始读取 | 关闭自动滚动，控制台切到历史内容 |
| 选择另一个历史文件 | 保持停止与空缓冲 | 取消旧读取，只有新选择的响应可写入 | 选择行与内容随新响应更新 |
| 返回实时 | 页面级 `enabled` 从 false 变 true，立即重读并重建轮询；若此前手动暂停，工作区先恢复暂停标记 | 取消在途读取，清空选择与历史内容 | 恢复自动滚动，控制台切回实时缓冲 |
| Activity 隐藏（历史模式） | 保持停止 | 取消列表与读取；进行中的读取转为 `cancelled`，选择与已显示内容保留 | Effects 清理，状态保留 |
| Activity 恢复（历史模式） | 不启动轮询 | 重读文件列表；上次读取被取消时重试当前文件 | 恢复后不会重新轮询实时日志 |

返回实时不手动调用 `start()`：模式由 `enabled = !viewing` 驱动，避免在历史模式下绕过页面级停用。进入历史时先停止并清空实时缓冲，因此返回实时后不会短暂显示进入前的旧行；立即重读会再次替换服务端快照。

页面真正重挂载或浏览器刷新会创建新的实时流与历史会话，缓冲、选择、过滤与滚动状态全部重置，与迁移前一致。

### 3. 历史列表与读取裁决

| 项目 | 当前值 | 依据 |
| --- | --- | --- |
| 文件列表 | `GET /agent/logs/files` | `features/logs/api` 的 `getLogFiles` |
| 文件内容 | `GET /agent/logs/files/:encodedPath?lines=1000` | `readLogFile`；服务端把 `lines` 限制在 1–5000 |
| 列表顺序 | 服务端按修改时间倒序 | `server/services/maaService.js` 的 `getLogFiles` |
| 内容语义 | 文件末尾 N 行的快照 | 与实时快照一致；没有 cursor、offset 或增量序号 |
| 选择标识 | 文件 `path` | “已有 cursor 状态”在本域表现为当前选择与读取相位 |

请求裁决：

- 文件列表与文件读取各自持有递增请求序号和独立 `AbortController`；`signal` 一直传到 `fetch`。
- 新选择、返回实时、Activity 隐藏/卸载以及新的列表请求都会中止旧请求。只有仍是当前请求、未中止且会话仍活跃的响应可以写入。
- 历史响应只写历史快照，不可能覆盖新选择或实时缓冲；返回实时后迟到的历史内容被丢弃。
- 列表请求失败保留上一次成功的文件列表并单独暴露 `filesError`；读取请求失败保留当前选择并暴露 `error`，用户可直接选择其他文件或点击“重新加载”重试。
- 列表刷新成功时会同步当前选择的元数据（大小、修改时间）；文件暂时不在列表里不自动退出历史模式，只有清理命令确认删除后执行选择裁决。

错误展示与迁移前的差异：历史列表错误与文件读取错误不再共用一个字段。读取失败时文件列表仍然可用，便于直接换一个文件；列表加载失败在历史模式下也会显示错误与重试，而不是只留下空列表。此变化只涉及失败状态，默认渲染结构、CSS 与截图不变。

### 4. Activity 生命周期

| 事件 | 历史会话行为 | 页面结果 |
| --- | --- | --- |
| Activity 隐藏或真正卸载 | `stop()`：取消列表与读取请求；进行中的读取转为 `cancelled`，不清空选择或已显示内容 | 不再写入隐藏期间完成的响应，loading 不会残留 |
| Activity 显示 | `start()`：重读文件列表；若上次读取被隐藏取消，重试当前文件 | 无需手动点击“重新加载”；历史模式不启动实时轮询 |
| 读取已成功或已明确失败 | 不因 Activity 恢复自动重读 | 保留内容或错误，由用户决定是否重试 |
| 文件列表读取中隐藏 | 取消列表请求并回到非 loading 相位 | 显示时重新读取列表 |
| 浏览器文档隐藏 | 不专门处理历史读取 | 实时轮询由 `RealtimeLogStream` 暂停；历史读取继续 |
| 真正重挂载 / 刷新 | 会话销毁，所有选择与内容重置 | 与迁移前一致 |

历史读取在 Activity 隐藏后完成不应留下 loading；恢复时应自动重试被取消的当前文件。明确失败仍不自动重试，避免隐藏期间反复请求坏文件。

### 5. 清空实时与清理历史

| 命令 | 前置协调 | 成功 | 失败 |
| --- | --- | --- | --- |
| 清空实时日志 | `pause()` 取消在途轮询；只在实时模式可用 | `POST /agent/logs/recent/clear` 确认后 `clear()` 清空实时缓冲与错误；此前未手动暂停时 `finally resume()` 立即重读空快照，手动暂停则保持暂停 | 保留原实时缓冲与错误；未手动暂停时恢复轮询；返回失败提示 |
| 清理历史文件 | 无实时动作；历史按钮在历史模式下禁用 | `POST /agent/logs/cleanup {maxSizeMB:10}` 确认后重读文件列表；若当前选择已不在列表中则退出历史模式 | 不刷新列表、不改变选择；返回失败提示 |

- 两个命令共用一个在途槽位：执行期间清空/清理按钮禁用，确认弹层自身也阻止重复提交。
- 页面卸载时取消命令的本地等待；服务端已收到的清空/清理动作不会被撤销。重新挂载后实时流重读服务端快照、历史会话重读文件列表，不依赖卸载前的命令结果。
- 清空实时不触碰历史文件列表与选择；清理历史不触碰实时缓冲或轮询。协议没有 cursor，因此没有需要重置的分页游标。
- 清理已成功但列表重读失败仍视为清理成功（删除已经发生），由历史会话显示列表错误与重试。
- 确认弹层、成功/失败通知与错误内联展示保持原交互；失败时弹层保持打开，可直接重试。

### 6. 页面保留状态

- 摘要/原始、级别、搜索与折叠是工作区状态，切换实时/历史、读取失败与重试都不会重置，便于在历史结果上继续同一过滤条件。
- 自动滚动在进入历史时关闭并禁用开关，返回实时时重新打开；历史内容不参与自动滚动 Effect（Effect 归 `LogConsole`）。
- 导出使用当前过滤后的行；历史与实时共用同一导出入口，不导出折叠后的重复计数。文本与文件名规则由 `model/logExport.ts` 固定。
- 工具栏暂停/继续按钮只在实时模式出现；清空时保留手动暂停，从历史返回实时会恢复手动暂停。按钮可访问名称随动作变化。
- 未改变端点、响应形状、存储键或服务端协议；清空/清理 API 只在末尾追加可选 `signal`，旧调用无需修改；未新增 Query key 或缓存。

### 7. 兼容与维护约束

- 历史读取与清空/清理继续经过 `HistoryLogSession`、`useHistoryLogs`、`useLogsSession` 与 `logCommands`；面板不另建请求序号、mounted 守卫或命令处理器。
- Activity 隐藏取消在途历史读取时必须结束 loading；恢复后重试被取消的当前文件，保持下列生命周期回归。
- 实时流与解析模型未修改；接口、轮询频率与暂停语义保持不变。
