# 历史日志与清理协调

> [← 返回文档索引](README.md)

本文描述 FPR-028 交付的日志历史会话与清理命令。它回答：实时与历史如何切换；历史文件列表、当前选择与读取状态归谁；旧响应如何裁决；Activity 隐藏/恢复如何避免卡在 loading；清空实时与清理历史分别协调哪些状态。实时轮询与解析模型仍见[实时日志流生命周期](logs-realtime-stream.md)。

## 1. 归属与边界

| 内容 | 唯一归属 | 说明 |
| --- | --- | --- |
| 实时缓冲、轮询计时器、在途读取与手动暂停 | `client/src/features/logs/model/realtimeLogStream.ts` | FPR-027 交付；历史读取不写入该缓冲 |
| 历史文件列表、当前选择、读取内容与读取/列表相位 | `client/src/features/logs/model/historyLogSession.ts` 的 `HistoryLogSession` | 会话数据，不进入 Query；同一时刻最多一个在途列表请求与一个在途文件读取 |
| 实时/历史模式、进入与返回、清空/清理命令的共用槽位 | `client/src/features/logs/hooks/useLogsSession.ts` | 组合两个会话；页面只消费该协议 |
| 清空实时与清理历史的请求协调 | `client/src/features/logs/model/logCommands.ts` | 纯命令函数，端口注入实时流/历史会话动作，便于直接测试 |
| 摘要/原始、级别、搜索、折叠、自动滚动、确认弹层与通知 | `client/src/features/logs/components/LogsWorkspace.tsx` 与工具栏/列表/历史选择器面板 | 最近的日志面板；不属于会话缓冲，组合边界见[日志领域面板](logs-panel.md) |

历史文件列表与文件读取是页面会话数据，不是可缓存的普通资源：列表在每次页面显示时重读，读取没有分页缓存；两者都不进入 TanStack Query。

## 2. 实时与历史切换协议

| 动作 | 实时流 | 历史会话 | 页面 |
| --- | --- | --- | --- |
| 选择历史文件 | `stop()` 清计时器并取消在途读取；`clear()` 清空缓冲与错误 | 若在历史中先取消旧读取；设置当前选择并开始读取 | 关闭自动滚动，控制台切到历史内容 |
| 选择另一个历史文件 | 保持停止与空缓冲 | 取消旧读取，只有新选择的响应可写入 | 选择行与内容随新响应更新 |
| 返回实时 | 页面级 `enabled` 从 false 变 true，立即重读并重建轮询；若此前手动暂停，工作区先恢复暂停标记 | 取消在途读取，清空选择与历史内容 | 恢复自动滚动，控制台切回实时缓冲 |
| Activity 隐藏（历史模式） | 保持停止 | 取消列表与读取；进行中的读取转为 `cancelled`，选择与已显示内容保留 | Effects 清理，状态保留 |
| Activity 恢复（历史模式） | 不启动轮询 | 重读文件列表；上次读取被取消时重试当前文件 | 恢复后不会重新轮询实时日志 |

返回实时不手动调用 `start()`：模式由 `enabled = !viewing` 驱动，避免在历史模式下绕过页面级停用。进入历史时先停止并清空实时缓冲，因此返回实时后不会短暂显示进入前的旧行；立即重读会再次替换服务端快照。

页面真正重挂载或浏览器刷新会创建新的实时流与历史会话，缓冲、选择、过滤与滚动状态全部重置，与迁移前一致。

## 3. 历史列表与读取裁决

| 项目 | 当前值 | 依据 |
| --- | --- | --- |
| 文件列表 | `GET /agent/logs/files` | `features/logs/api` 的 `getLogFiles` |
| 文件内容 | `GET /agent/logs/files/:encodedPath?lines=1000` | `readLogFile`；服务端把 `lines` 限制在 1–5000 |
| 列表顺序 | 服务端按修改时间倒序 | `server/services/maaService.js` 的 `getLogFiles` |
| 内容语义 | 文件末尾 N 行的快照 | 与实时快照一致；没有 cursor、offset 或增量序号 |
| 选择标识 | 文件 `path` | “已有 cursor 状态”在本域表现为当前选择与读取相位 |

请求裁决：

- 文件列表与文件读取各自持有递增请求序号和独立 `AbortController`；`signal` 一直传到 `fetch`。
- 新选择、返回实时、Activity 隐藏/卸载以及新的列表请求都会中止旧请求。只有仍是当前请求、未中止且会话仍活跃的响应可以写入。
- 历史响应只写历史快照，不可能覆盖新选择或实时缓冲；返回实时后迟到的历史内容被丢弃。
- 列表请求失败保留上一次成功的文件列表并单独暴露 `filesError`；读取请求失败保留当前选择并暴露 `error`，用户可直接选择其他文件或点击“重新加载”重试。
- 列表刷新成功时会同步当前选择的元数据（大小、修改时间）；文件暂时不在列表里不自动退出历史模式，只有清理命令确认删除后执行选择裁决。

错误展示与迁移前的差异：历史列表错误与文件读取错误不再共用一个字段。读取失败时文件列表仍然可用，便于直接换一个文件；列表加载失败在历史模式下也会显示错误与重试，而不是只留下空列表。此变化只涉及失败状态，默认渲染结构、CSS 与截图不变。

## 4. Activity 生命周期

| 事件 | 历史会话行为 | 页面结果 |
| --- | --- | --- |
| Activity 隐藏或真正卸载 | `stop()`：取消列表与读取请求；进行中的读取转为 `cancelled`，不清空选择或已显示内容 | 不再写入隐藏期间完成的响应，loading 不会残留 |
| Activity 显示 | `start()`：重读文件列表；若上次读取被隐藏取消，重试当前文件 | 无需手动点击“重新加载”；历史模式不启动实时轮询 |
| 读取已成功或已明确失败 | 不因 Activity 恢复自动重读 | 保留内容或错误，由用户决定是否重试 |
| 文件列表读取中隐藏 | 取消列表请求并回到非 loading 相位 | 显示时重新读取列表 |
| 浏览器文档隐藏 | 不专门处理历史读取 | 实时轮询由 `RealtimeLogStream` 暂停；历史读取继续 |
| 真正重挂载 / 刷新 | 会话销毁，所有选择与内容重置 | 与迁移前一致 |

FPR-027 记录的两个既有缺口在本项关闭：历史读取在 Activity 隐藏后完成不再留下 loading；恢复时会自动重试被取消的当前文件。明确失败仍不自动重试，避免隐藏期间反复请求坏文件。

## 5. 清空实时与清理历史

| 命令 | 前置协调 | 成功 | 失败 |
| --- | --- | --- | --- |
| 清空实时日志 | `pause()` 取消在途轮询；只在实时模式可用 | `POST /agent/logs/recent/clear` 确认后 `clear()` 清空实时缓冲与错误；此前未手动暂停时 `finally resume()` 立即重读空快照，手动暂停则保持暂停 | 保留原实时缓冲与错误；未手动暂停时恢复轮询；返回失败提示 |
| 清理历史文件 | 无实时动作；历史按钮在历史模式下禁用 | `POST /agent/logs/cleanup {maxSizeMB:10}` 确认后重读文件列表；若当前选择已不在列表中则退出历史模式 | 不刷新列表、不改变选择；返回失败提示 |

- 两个命令共用一个在途槽位：执行期间清空/清理按钮禁用，确认弹层自身也阻止重复提交。
- 页面卸载时取消命令的本地等待；服务端已收到的清空/清理动作不会被撤销。重新挂载后实时流重读服务端快照、历史会话重读文件列表，不依赖卸载前的命令结果。
- 清空实时不触碰历史文件列表与选择；清理历史不触碰实时缓冲或轮询。协议没有 cursor，因此没有需要重置的分页游标。
- 清理已成功但列表重读失败仍视为清理成功（删除已经发生），由历史会话显示列表错误与重试。
- 确认弹层、成功/失败通知与错误内联展示保持原交互；失败时弹层保持打开，可直接重试。

## 6. 页面保留状态

- 摘要/原始、级别、搜索与折叠是工作区状态，切换实时/历史、读取失败与重试都不会重置，便于在历史结果上继续同一过滤条件。
- 自动滚动在进入历史时关闭并禁用开关，返回实时时重新打开；历史内容不参与自动滚动 Effect（Effect 归 `LogConsole`）。
- 导出使用当前过滤后的行；历史与实时共用同一导出入口，不导出折叠后的重复计数。文本与文件名规则由 `model/logExport.ts` 固定。
- 工具栏暂停/继续按钮只在实时模式出现（FPR-035）；清空时保留手动暂停，从历史返回实时会恢复手动暂停。按钮可访问名称随动作变化。
- 未改变端点、响应形状、存储键或服务端协议；清空/清理 API 只在末尾追加可选 `signal`，旧调用无需修改；未新增 Query key 或缓存。

## 7. 兼容与回滚

- 可单独回退 `HistoryLogSession`、`useHistoryLogs`、`useLogsSession` 与 `logCommands`，恢复页面内的历史请求序号、mounted 守卫与清空/清理处理器；服务端无需配合。FPR-035 的面板拆分不影响这些会话所有者，回退面板组合即可恢复内联页面。
- 回退后旧缺口会重新出现：Activity 隐藏期间完成的历史读取可能留下 loading，恢复不重试当前文件。
- 实时流与解析模型未修改；FPR-027 的接口、轮询频率与暂停语义保持不变。
